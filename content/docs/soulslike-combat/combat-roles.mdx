> Slot limits stop every enemy from attacking at once. Fitness scoring picks who fills each slot. Role changes swap behavior assets.

## When to Use This

- Multiple enemies that should not all press the player together.
- Soulslike-style turn-taking or staggered pressure.
- Per-enemy archetypes (front-line Attacker vs hanging-back Waiter) driven by the same controller class.
- Tuning difficulty by changing how many Attackers a target pool allows.

The role system is optional: disable auto-registration on bosses or ambient AI that should not participate.

---

## Built-in Roles

Roles are `SEC.Role.*` gameplay tags. Add custom tags under `SEC.Role` in **Project Settings → Gameplay Tags**, then list them in **Plugins → Soulslike Enemy Combat → Additional Roles**.

| Role | Tag | Typical use |
|------|-----|-------------|
| None | `SEC.Role.None` | No coordinated role (fallback when no slot fits). |
| Attacker | `SEC.Role.Attacker` | Primary melee pressure. |
| Waiter | `SEC.Role.Waiter` | Holds distance, waits for a slot. |
| Flanker | `SEC.Role.Flanker` | Circles for angle attacks. |
| Supporter | `SEC.Role.Supporter` | Ranged or support abilities from the back. |
| Elite | `SEC.Role.Elite` | Boss-tier enemy; unlimited slots by default. |

Roles are **reassigned on a timer**. The subsystem scores every (AI, role) pair for each combat target pool, respects slot limits, then notifies controllers when assignments change.

## Project Settings: Slots and Timing

Open **Project Settings → Plugins → Soulslike Enemy Combat**.

### Role limits

`Role Limits` is an array of `{ Role, Limit }`. Roles **not** in the array have **unlimited** slots.

Plugin defaults (from `USoulslikeEnemyCombatSettings` constructor):

| Role | Default limit |
|------|---------------|
| Attacker | 3 |
| Flanker | 2 |
| Supporter | 2 |
| Waiter | unlimited |
| Elite | unlimited |
| None | unlimited |

Override a limit at runtime with `SetRoleLimitOverride` (`-1` = unlimited, `0` = disable the role). See the **Runtime control API** collapsible below.

### Reassignment timing

<CombatRoleTimingDetails />

- **`RoleReassignmentInterval`** (default `8` s): how often `EvaluateRoleDistribution` runs. Set to `0` for manual-only reassignment via `ForceReassignment`.
- **`MinTimeInRole`** (default `8` s): hysteresis. While an AI is still within this window in its **current** role, the evaluator adds `+0.3` to that role's adjusted fitness so assignments do not thrash.
- **`bReevaluateTargetsOnReassignment`**: when **two or more** combat targets are registered, re-run each AI's `TargetSelector` at the start of each timer tick (before role evaluation). No effect with a single target. Per-enemy opt-out: `bIgnoreTargetRedistribution` on `EnemyAIConfig`.

## EnemyAIConfig Setup

Create **Right-click → Miscellaneous → Data Asset → EnemyAIConfig** and assign it on the pawn (`IEnemyAIConfigProvider`) or on `SECCombatControllerComponent → Default AI Config`.

### Combat role fields

<CombatRoleConfigDetails />

| Field | Notes |
|-------|-------|
| **Auto-Register for Combat Roles** | When true, `SECCombatControllerComponent` calls `RegisterCombatant` on possess. Config value wins over the component default. |
| **Allowed Roles** | Empty = any built-in/custom role. Restrict archers to `Waiter` + `Supporter`, for example. |
| **Priority** | Tiebreaker when adjusted fitness scores match. Typical: `0` grunt, `50` elite, `100` mini-boss. |
| **Preferred Role** | Small fitness bonus (`+0.05` to adjusted fitness) when scoring that role tag. |
| **Fitness Evaluators** | Instanced `URoleEvaluator` objects. Empty = distance-only fallback (closer = higher score, capped at 2000 cm). |
| **Target Selector** | Picks which registered combat target this AI joins when several exist. Falls back to project **Default Target Selector**. |
| **Ignore Target Redistribution** | Skips periodic target re-evaluation for this AI (bosses with a fixed target). |

### Map roles to behavior assets

When a role changes, `SECCombatControllerComponent::SyncStateForCombatRole` resolves and applies:

| Asset | Config section | Managed by |
|-------|----------------|------------|
| [ActionSet](/docs/soulslike-combat/action-system) | `RoleActionSets` / `DefaultActionSet` | `bManageActionSetsAutomatically` |
| [ReactionSet](/docs/soulslike-combat/reaction-system) | `RoleReactionSets` / `DefaultReactionSet` | `bManageReactionSetsAutomatically` |
| [Movement profile](/docs/soulslike-combat/movement-system) | `RoleMovementProfiles` / `DefaultMovementProfile` | `bManageMovementProfilesAutomatically` |

Unlisted roles use the **Default** asset for that category. Weapon overrides still win over config role entries (same resolution order as actions/reactions).

## Register a Combat Target

Enemies **register as combatants** on possess, but **`AssignRoleToNewCombatant` skips role assignment until the combatant has an `AssignedTarget`**. Periodic evaluation also skips combatants with no assigned target.

On player spawn (or when combat starts), call on the server:

```cpp
UAICombatRoleSubsystem* Roles = GetWorld()->GetSubsystem<UAICombatRoleSubsystem>();
Roles->RegisterCombatTarget(PlayerPawn, /*bAutoAssignUnassigned=*/true);
```

- **`RegisterCombatTarget`**: primary API. Adds the actor to the target pool.
  - **`bAutoAssignUnassigned`**: assigns every unassigned combatant to this target (skips team-friendly pairs), then calls `ForceReassignment` and `EvaluateRoleDistribution`.
  - **`bReevaluateExisting`**: calls `ReevaluateAllTargets()` so already-assigned combatants re-run their `TargetSelector` (respects `bIgnoreTargetRedistribution`).
- **`SetCombatTarget`**: deprecated wrapper that calls `RegisterCombatTarget(NewTarget, true)` (auto-assign only; no `bReevaluateExisting`).
- **`AddCombatTarget`**: adds a target to the pool without assignment logic. Prefer `RegisterCombatTarget` unless you are building custom flow.

Each registered target keeps its **own role pool** (two players can each have up to three Attackers independently). Multi-target APIs live in the **Multi-target control** collapsible below.

## Runtime Flow

1. Controller possesses pawn → `SECCombatControllerComponent` resolves `EnemyAIConfig` (pawn `IEnemyAIConfigProvider`, else `DefaultAIConfig`).
2. If auto-register is on → `UAICombatRoleSubsystem::RegisterCombatant` (requires `AAIController`).
3. Combatant gets a target via `InitialTarget` (runtime-only on registration params), `TargetSelector`, or the first registered combat target when `RegisterCombatTarget` runs.
4. If a target is assigned → `AssignRoleToNewCombatant` slots the newcomer without a full pool reshuffle.
5. On **`RoleReassignmentInterval`**, `EvaluateRoleDistribution` groups combatants by assigned target, scores every (AI, role) pair, sorts by adjusted fitness then **Priority**, and greedily fills slots per pool.
6. `NotifyRoleChange` → `SECCombatControllerComponent::HandleCombatRoleAssigned` (when that component exists) → replicates role to `SECCombatRoleComponent` and runs **`SyncStateForCombatRole`**.

Combatants with no acceptable open slot in the greedy pass end up on **`SEC.Role.None`**. Until first assignment, `CurrentRole` may be an empty tag (`FGameplayTag::EmptyTag`).

## When the Role Changes

`EnemyControllerBase` already owns `SECCombatControllerComponent`. On role change it:

1. Writes the tag to **`SECCombatRoleComponent`** on the pawn (replicated to clients).
2. Calls **`SyncStateForCombatRole`**, which syncs action set, reaction set, and movement profile for the new tag.

Custom controllers need **`SECCombatControllerComponent`** on the `AAIController` (or manual calls to `USECCombatRoleSyncLibrary`) or `NotifyRoleChange` will broadcast globally but **will not sync** action/reaction/movement assets.

<Collapsible title="Manual sync for custom controllers" badge="Alternative">

`USECCombatRoleSyncLibrary` mirrors what `SyncStateForCombatRole` does:

| Function | Syncs |
|----------|-------|
| `SyncAllForCombatRole(Controller, Pawn, RoleTag, AIConfig)` | Action + reaction + movement |
| `SyncActionSetForRole(Pawn, RoleTag)` | `SECActionSetComponent` only |
| `SyncReactionSetForRole(Pawn, RoleTag)` | `SECReactionSetComponent` only |
| `SyncMovementProfileForRole(Controller, RoleTag, AIConfig)` | `MovementEvaluatorComponent` only |

Bind to `UAICombatRoleSubsystem::OnCombatRoleChanged` or `SECCombatControllerComponent::OnCombatRoleChanged`, then call sync with the new tag and resolved `EnemyAIConfig`.

</Collapsible>

## Client Role Visibility

The subsystem runs on the server (controllers are server-only). **`SECCombatRoleComponent`** on the pawn replicates the current role tag for UI, VFX, or debug.

- Added by **`EnemyCharacterBase`** by default.
- Server writes via `SetCombatRole` inside `HandleCombatRoleAssigned`.
- Clients read `GetCombatRole()` or bind to `OnCombatRoleChanged`.
- Client-side `SetCombatRole` is a no-op.

## Bosses and Opt-Out AI

| Goal | Setting / API |
|------|----------------|
| Skip slot coordination entirely | `bAutoRegisterForCombatRoles = false` on `EnemyAIConfig`. |
| Stay on one player when targets shuffle | `bIgnoreTargetRedistribution = true` (skips that AI during `ReevaluateAllTargets` and periodic target re-evaluation). |
| Script a role without the evaluator changing it | `ForceAssignRole(Controller, Role, bLockRole = true)`. |
| Local-only role (no slot use) | `ApplyLocalCombatRole` on `SECCombatControllerComponent` (warns if still registered). |

Unregistered AI can still use ActionSets and movement profiles manually; they just do not consume role slots.

### Distance Evaluator (`UDistanceRoleEvaluator`)

Scores distance to the combat target. C++ constructor defaults **`Role Influence Weights`** to `{ SEC.Role.Attacker: 1.0 }`; other fields:

<DistanceRoleEvaluatorDetails />

Example: closer enemies should be Attackers → **Ideal Distance** `0`, **Effective Range** `2000`, **Score Mode** *Higher Score = Better Fit*, **Role Influence Weights** `{ Attacker: 1.0 }`.

Far enemies should be Waiters → same distance fields, **Score Mode** *Lower Score = Better Fit*, weights `{ Waiter: 1.0 }`.

<Collapsible title="Custom URoleEvaluator subclass" badge="Advanced">

`URoleEvaluator` is `Abstract`, `Blueprintable`, `EditInlineNew`. Override **`EvaluateFitness`** (returns raw `0.0–1.0`; the subsystem applies **Role Influence Weights** and **Score Mode** via `GetFinalScore`).

`FRoleEvaluationContext` fields:

| Field | Use |
|-------|-----|
| `Controller` | Access pawn, components, target via `GetCombatantTarget`. |
| `Role` | Role being scored. |
| `CurrentRole` | Assigned role today. |
| `TimeInCurrentRole` | Seconds in current role. |

Multiple evaluators combine by **weighted average** (weight = each evaluator's influence for that role tag).

</Collapsible>

<Collapsible title="Runtime control API" badge="Advanced">

Subsystem: **`UAICombatRoleSubsystem`** (world subsystem).

**Configuration**

| Function | Purpose |
|----------|---------|
| `SetReassignmentInterval` | Seconds between auto evaluations (`0` = off). |
| `SetMinTimeInRole` | Hysteresis window. |
| `SetReevaluateTargetsOnReassignment` | Toggle target re-pick before role eval (multi-target). |
| `SetRoleLimitOverride` / `ClearRoleLimitOverride` / `ClearAllRoleLimitOverrides` | Runtime slot caps. |
| `UpdateConfig(FAICombatRoleConfig, bLimitAttritionEnabled, bForceReevaluation)` | Bulk update; attrition mode lets existing holders keep roles when limits shrink. |
| `ResetToDefaultSettings` | Clear runtime overrides. |

**Manual assignment**

| Function | Purpose |
|----------|---------|
| `ForceAssignRole(Controller, Role, bLockRole)` | Bypass evaluation; optional lock. |
| `UnlockRole` | Re-enable evaluation for a locked combatant. |
| `ForceReassignment` / `ForceReassignmentForTarget` | Immediate re-eval. |
| `PauseReassignment` / `ResumeReassignment` | Freeze role changes (cutscenes). |
| `StartReassignmentTimer` / `StopReassignmentTimer` | Timer control when interval is `0`. |

**Query**

| Function | Purpose |
|----------|---------|
| `GetRole` / `GetRoleCount` / `GetCombatantsWithRole` | Current assignments. |
| `IsRegistered` / `IsRoleLocked` / `GetAllCombatants` | Pool membership. |

```cpp
// Enrage: allow three Attackers, then re-evaluate immediately
UAICombatRoleSubsystem* RoleSys = GetWorld()->GetSubsystem<UAICombatRoleSubsystem>();
RoleSys->SetRoleLimitOverride(
    USoulslikeEnemyCombatSettings::GetRoleAttacker(), 3);
RoleSys->ForceReassignment();
```

</Collapsible>
