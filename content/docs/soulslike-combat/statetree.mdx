## Available StateTree Tasks

| Task | Purpose | When to Use |
|------|---------|-------------|
| `STTask_BuildDecisionContext` | Gathers combat data | Every tick in root state |
| `STTask_AIMovement` | Evaluates and applies movement | Every tick in root state |
| `STTask_PollAction` | Scores and selects action | On entering decision state |
| `STTask_DoAction` | Triggers execution of chosen action | On entering execute state |
| `STTask_UpdateActionSet` | Swaps ActionSet | When changing AI behavior |
| `STTask_PollCombatRole` | Polls current combat role | Every tick, outputs role tag |
| `STTask_PollFocusActor` | Polls controller focus actor | Every tick, outputs target reference |
| `STTask_SyncActionSet` | Syncs ActionSet from pawn's SECActionSetComponent | On entering role state |
| `STTask_SyncMovementProfile` | Syncs MovementProfile for current role | On entering role state |
| `STTask_PollLastKnownLocation` | Outputs a target's last-known location | Investigate / search states (move to where it was last seen) |

> All StateTree tasks work with any `AAIController` that has a `SECCombatControllerComponent`. They use the component's static resolution helpers to find AIConfig and combat role data.

## Available StateTree Conditions

| Condition | Purpose | When to Use |
|-----------|---------|-------------|
| `STCondition_ASCHasTag` | Checks the pawn's ASC for gameplay tags | Gate states by ability/status tags |
| `STCondition_AwarenessState` (**Awareness State At Least**) | Passes when a target's awareness state is ≥ a minimum | Branch Patrol / Investigate / Combat / Search on what the AI has perceived |

## Typical StateTree Structure

```
Root (Always Active)
├─ BuildDecisionContext [Tick]
├─ AIMovement [Tick]
│
├─ Idle State
│  └─ Transition → Combat (when target acquired)
│
└─ Combat State
   ├─ Decision State
   │  ├─ PollAction [Enter]
   │  └─ Transition → Execute (when action chosen)
   │
   └─ Execute State
      ├─ DoAction [Enter]
      └─ Transition → Decision (when complete)
```

## Task Details

### STTask_BuildDecisionContext

**Inputs:**
- AIController (Object)

Tuning that used to live on the task (aggression baseline, window cadence, line-of-sight trace channel) moved onto the config. Set it under `UEnemyAIConfig` > Behavior > **Decision Context Params**. The task resolves those params on EnterState via `USECDecisionLibrary::ResolveDecisionParams`, so every AI that shares a config shares the same tunables. See [Decision Context Params](/docs/soulslike-combat/configuration#decision-context-params) in the configuration reference.

**Outputs:**
- OutDecisionContext (FDecisionContext struct)

**What it does:**
- Calculates distance and angle to the target
- Reads AI health from `UBasicHealthComponent` (or 1.0 when no component is present); Stamina is fixed at 100. For GAS attribute-backed health or stamina, add an Attribute Scorer or Attribute Gate on the action rather than sourcing it into the context.
- Gathers tags from the AI's ASC (`SelfTags`), the target's ASC (`TargetTags`), and `USECWorldTagSubsystem` (`WorldTags`)
- Traces line of sight from the AI's eyes to the target and writes `bHasLOS`. Actions flagged **Require Line Of Sight** use it as a hard gate. The trace channel and complexity come from Decision Context Params.

---

### STTask_PollAction

**Inputs:**
- AIController
- Context (FDecisionContext)
- EvaluationCooldown
- DebugLog

**Outputs:**
- ChosenAction (FChosenAction)

**What it does:**
- Scores all actions in the ActionSet
- Runs each action's Scorers and Gates
- Checks cooldowns
- Selects the best valid action

---

### STTask_DoAction

**Inputs:**
- Actor
- AIController
- InChosenAction (FChosenAction)
- DebugLog

**What it does:**
- If Ability: Activates via ASC
- If BT: Runs behavior tree sequence
- Waits for SEC.Action.End event
- Completes when action finishes

## Reading the Decision Context Outside the Task

`STTask_BuildDecisionContext` builds `FDecisionContext` by calling `USECDecisionLibrary::CalculateDecisionContext`; `ActionEvaluationComponent` then consumes that context for scoring. The same calculation is exposed as Blueprint nodes so you can read the current decision inputs from your own logic (HUD, debug overlays, gameplay scripts) without standing up a separate evaluation. They run the same math the task runs, so the values match what scoring sees.

| Node | Returns | Notes |
|------|---------|-------|
| `Get Decision Context (AI Controller)` | `FDecisionContext` | Pass the AIController. Resolves tunables from its config. |
| `Get Decision Context (Pawn)` | `FDecisionContext` | Convenience wrapper; resolves the pawn's AIController first. |
| `Resolve Decision Params` | `FSECDecisionContextParams` | Returns the config's [Decision Context Params](/docs/soulslike-combat/configuration#decision-context-params), or struct defaults when no config is found. |

All three are server-only and return a default-constructed result off the authority.

> A getter call uses a fresh window and seed, so its `WindowId` / `Seed` fields will not match the cadence of the running StateTree task. Use it to read the live spatial, health, threat, and tag fields. It will not reproduce score variation.

## Awareness Nodes

These two nodes let the brain branch on what the AI has *perceived* (via the [Awareness System](/docs/soulslike-combat/awareness-system)), so you can build patrol → investigate → combat → search loops without wiring delegates by hand.

### STCondition_AwarenessState — "Awareness State At Least"

**Inputs:**
- AIController (Object, Context)
- `Target` (Actor) - the target to test. Leave empty to test the AI's **most-aware** target.
- `MinState` (ESECAwarenessState) - passes when the target's state is ≥ this. Default `Detected`.
- `bInvertResult` (bool)

**What it does:**
- Reads `GetAwarenessState(Target)` from the controller's awareness component and compares it to `MinState` (ordering: Unknown < Forgotten < Suspicious < Lost < Detected).
- Gate a Combat state with `MinState = Detected`, an Investigate state with `MinState = Suspicious`, and so on.

### STTask_PollLastKnownLocation

**Inputs:**
- AIController (Object, Context)
- `Target` (Actor) - the target to read. Leave empty to use the AI's most-aware target.

**Outputs:**
- `LastKnownLocation` (FVector) - bind this straight into an **AI Move To** destination
- `AgeSeconds` (float) - how stale the location is
- `bValid` (bool) - false if there is no recorded location
- `ResolvedTarget` (Actor) - the target actually read (handy with the most-aware fallback)

**What it does:**
- Each tick, reads `GetLastKnownLocation` for the target and exposes it as bindable outputs - the core of "search where I last saw you" behavior.
