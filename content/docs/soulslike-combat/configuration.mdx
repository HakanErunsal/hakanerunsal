## UAICombatConfig (Data Asset)

Defines combat role selection, behavior logic, and action set binding for an AI.

### Example Profile

```cpp /DA_SEC_CombatConfig_Default/ /DA_SEC_ActionSet_Attacker/ /DA_SEC_ActionSet_Waiter/ /DA_SEC_ActionSet_Flanker/ /DA_SEC_ActionSet_Ranged/
Name: DA_SEC_CombatConfig_Default

CombatRole
  AutoRegisterForCombatRoles: true

RoleRegistration
  AllowedRoles:
    - SEC.Role.Attacker
    - SEC.Role.Flanker
    - SEC.Role.Supporter
    - SEC.Role.Waiter
  Priority: 0
  PreferredRole: SEC.Role.Attacker

FitnessEvaluators
  - DistanceEvaluator
  - BP_HealthEvaluator
  - BP_RandomEvaluator

Behavior
  StateTree: StateTree_SEC_Core

ActionSets
  ManageActionSetsAutomatically: true
  DefaultActionSet: DA_SEC_ActionSet_Attacker

RoleActionSets
  SEC.Role.Waiter
    Managed: true
    ActionSet: DA_SEC_ActionSet_Waiter

  SEC.Role.Flanker
    Managed: true
    ActionSet: DA_SEC_ActionSet_Flanker

  SEC.Role.Supporter
    Managed: true
    ActionSet: DA_SEC_ActionSet_Ranged
```

>FitnessEvaluators are editor-instanced scoring objects.
Each evaluator computes a normalized fitness score based on the current AI context, such as distance, health, or randomness.
All active evaluators are executed during role selection, and their results are combined to determine the most suitable combat role. You can inherit from RoleEvaluator class and implement your own scoring and stack it inside the AIConfig, or use the existing ones i have created.


## UActionSet (Data Asset)

Contains an array of `FActionSpec` - all available actions for an AI.

### Creating an ActionSet

1. Right-click → Miscellaneous → Data Asset → `ActionSet`
2. Add actions to the Actions array
3. Configure each action's properties

### FActionSpec Structure

```cpp
struct FActionSpec
{
    // Identity
    FName Id;                          // Unique identifier
    FString DisplayName;               // Editor name
    EActionExecutionMode ExecutionMode; // Ability or BT
    
    // Gameplay Ability Mode
    FGameplayTag AbilityTag;           // Tag to activate
    FGameplayTag AbilityEndTag;        // Completion signal
    
    // Behavior Tree Mode
    TArray<UBehaviorTree*> BehaviorTrees;
    float BehaviorTreeTimeout;
    
    // Scoring
    FRangeEval Distance;               // Distance curve
    FRangeEval Angle;                  // Angle curve
    FRangeEval Health;                 // Health curve
    float BaseWeight;                  // Base priority

    // Cooldowns
    FActionCooldown Cooldown;
    
    // Chaining
    FName PrefferedNextAction;         // This action will receive a bonus on the next evaluation
    float ChainBonusMultiplier;        // Score bonus if chaining
    
    // Context
    FGameplayTagContainer RequiredTags;// Action is blocked if these tags don't exist on the AbilitySystemComponent
    FGameplayTagContainer BlockedTags; // Action is blocked if these tags exist on the AbilitySystemComponent
    FGameplayTagContainer AddTags;     // These tags will be given to the AbilitySystemComponent as long as this action is active
};
```

### FRangeEval Explained

```cpp
struct FRangeEval
{
    float MinValue;      // Invalid below this
    float OptimalMin;    // Score = 1.0 starts here
    float OptimalMax;    // Score = 1.0 ends here
    float MaxValue;      // Invalid above this
};

// Example: Distance range for melee attack
Distance.MinValue = 0;       // Valid from 0cm
Distance.OptimalMin = 100;   // Perfect from 100cm
Distance.OptimalMax = 250;   // Perfect until 250cm
Distance.MaxValue = 400;     // Invalid beyond 400cm

// Scoring visualization:
//   0    100       250      400
//   |-----|========|--------|
//   0.0   1.0     1.0      0.0
```

## UMovementBehaviorProfile (Data Asset)

Contains all parameters for `MovementEvaluatorComponent`.

### Example Profile

```cpp /DA_AggressiveMelee/
Name: DA_AggressiveMelee

Desired Distance: 300
DistanceTolerance: 0.15
EnableStrafeRest: true
StrafeRestTimeLimit: 10.0f
StrafeRestDuration: 1.0f

Positioning Rules {}
```

>PositioningRule is an editor-instanced UObject, you can derive from UPositioningRule, override function **EvaluateDirection**, this function will give you the context that is being tested, you can basically return a weight multiplier from this function. All PositioningRules that are stacked on your UMovementBehaviorProfile will be considered when making movement decisions.

### Using Profiles

```cpp
// In AI Controller BeginPlay:
MovementEvaluator->ApplyBehaviorProfile(AggressiveMeleeProfile);

// Or swap at runtime (e.g., boss phase change):
MovementEvaluator->ApplyBehaviorProfile(EnragedProfile);
```

## USECDamageConfig (Data Asset)

Contains damage values and type for melee attacks.

### Properties

```cpp
BaseDamage: 45.0
DamageType: UDmgType_Physical
ImpulseStrength: 1000.0
bCanCritical: true
CriticalMultiplier: 2.0
```

### Usage

Assigned to weapons, automatically applied during melee traces.
